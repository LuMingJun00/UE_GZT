UE 场景工作台 · 本地图生 3D 模型选型调研报告

调研日期：2026-11-02 ｜ 本机：NVIDIA RTX 4060 Ti 16GB + 32GB RAM + Windows 11（驱动 610.88）｜ 用途：替换 Tripo 云端 API 的「图生 3D」步骤（④减面暂缓、⑤批量导入 UE）
选型加权（质量优先）：图生3D质量（几何精度/水密性/细节保真/材质质感）> PBR 完整度 > GLB 可用性 > 速度（单资产 1–4 分钟可接受）> 显存（16GB 硬上限，可接受 FP16/量化/分段加载）> 部署简易度 > 许可

一、结论摘要

首选 · 方案 A：Hunyuan3D-2.1（质量最大化路径）

当前可本地部署的开源图生 3D 中第三方评测质量最高（上海 AI Lab 22 方法评测对象级综合第一的 Hunyuan 家族里唯一开源权重可部署版本），且原生输出真 PBR 三通道贴图（albedo/metallic/roughness）。本机 16GB 下官方明确 shape 阶段（10GB）可跑，texture 阶段（21GB）用 --low_vram_mode 把显存 offload 到 32GB 系统内存——但单资产预计 10–20 分钟，超出 1–4 分钟窗口，属于「质量优先、慢速档」，必须先实测 offload 在本机能否跑完。

次选 · 方案 B：TRELLIS v1（速度–质量均衡，ComfyUI 路线）

官方显存下限正好 16GB（本机 FP16 可跑），几何质量为第一梯队（上海 AI Lab 材质最佳提名），单资产预计 1–3 分钟落在可接受窗口；部署路径最成熟（ComfyUI 原生工作流，Windows 可行）。短板：仅烘焙单张 albedo 贴图、无 PBR，UE 材质需后补。适合作为 A 实测失败或嫌慢时的兜底。

快速 PBR 档 · 方案 C：Stable Fast 3D

6GB 显存、秒级出图、GLB 开箱导入 UE，输出 albedo + tangent normal 贴图；但 metalness/roughness 是整物体单一标量而非贴图，几何细节轻量（默认 27.4K 面）。适合快速原型/远景道具/大批量试错，不满足特写质量。许可：年营收 ≤100 万美元免费商用。

两个重要事实纠偏（已独立二次核验主源）：
  1. 腾讯 Hunyuan3D-2.5 / 3.0 / 3.1 从未开放模型权重（仅托管平台），本地部署不可行——可本地部署的最新版本是 2.1（2025-06 全开源含训练代码）。
  2. 阿里通义「青龙 / Qianlong」图生 3D 未查到（多组检索+核验均未命中；阿里百炼的图生 3D 实为 VAST Tripo 托管 API，与你正在停用的 Tripo 是同一家）。命中的「青龙」是 OpenLoong 人形机器人项目。
另：质量向新模型 Pixal3D（腾讯 ARC×清华，SIGGRAPH 2026，MIT，近重建级保真 + PBR 纹理 GLB）值得关注，但官方未承诺 16GB 可跑，列入观察清单待实测。

五、推荐方案详述

方案 A（首选，质量最大化）：Hunyuan3D-2.1 —— shape 本地 + texture 内存 offload

为什么是它：质量优先原则下，这是「第三方评测质量最高（上海 AI Lab 22 方法综合第一家族）+ 唯一真 PBR 三通道 + 16GB 可试」的组合。2.5/3.0/3.1 无权重，2.1 即当前可本地部署的最强版本（官方 README 明确 16GB 可跑 shape、texture 用 --low_vram_mode）。

部署步骤概要（实施轮细化）

  • 官方仓库 Tencent/Hunyuan3D-2（含训练代码，全开源）→ 拉取 Hunyuan3D-2.1 shape 3.0B + PBR-Paint 权重（HF tencent/Hunyuan3D-2.1）
  • 环境：Python 3.10 + PyTorch（CUDA 12.x）+ HuggingFace 权重自动下载；Windows 上首选 WSL2（官方主打 Linux），或按社区 Windows 教程（依赖偏 Linux，flash-attn 等需编译——需实测确认是否必需）
  • texture 阶段加 --low_vram_mode，把 21GB 显存需求 offload 到系统内存（32GB RAM 官方预期可试）
  • 包一层本地 HTTP 服务（子进程调用官方 inference 脚本 + 任务队列 + 轮询接口），供工作台对接

预期效果

质量上限最高：几何精度与细节保真为可本地部署模型中的第一档；PBR 三通道贴图（albedo/metallic/roughness）可直接用于 UE 材质；GLB 输出导入 UE 管线。

代价与风险（必须正视）

  • 16GB 上 texture 阶段单资产预计 10–20 分钟（社区估算），显著超出 1–4 分钟窗口——若批量生产不可接受，退回方案 B/C，或把 texture 阶段留到夜间/排队
  • offload 到系统内存是否稳定跑完需本机实测，无二手结论可依

实测验证要点

  1. --low_vram_mode 在 4060 Ti 16GB + 32GB RAM 上 texture 阶段能否跑完、实际耗时（官方声明 vs 本机实测）
  2. PBR 三通道贴图质量与几何水密性（与 Tripo P1 出图对照）
  3. Windows 部署路径（WSL2 vs 原生）哪个能跑通

方案 B（次选，速度–质量均衡）：TRELLIS v1 —— ComfyUI 原生工作流

为什么是它：官方显存下限正好 16GB（本机承诺可跑）、几何第一梯队、部署最成熟（ComfyUI Windows 原生支持）、单资产预计 1–3 分钟落在可接受窗口。质量短板是无 PBR（仅 albedo）。

部署步骤概要

  • 安装 ComfyUI Windows 一键包 → 官方 ComfyUI-TRELLIS 工作流 → 权重自动下载（microsoft/TRELLIS-image-large，FP16）
  • ComfyUI 自带 REST API（POST /prompt 提交工作流、GET /history 轮询）——与工作台异步轮询骨架天然契合

预期效果

16GB 内稳定运行，单资产 1–3 分钟；几何质量第一梯队（上海 AI Lab 材质最佳提名之一）；输出 GLB + 单张 albedo 贴图，UE 材质后补（UE 程序化材质/已有材质库，或叠加方案 C 的纹理烘焙——补偿效果需实测）。

实测验证要点

  1. 16GB 峰值显存与单资产实际耗时（验证 1–4 分钟窗口）
  2. 几何精度/水密性 vs Tripo P1 对照
  3. albedo 贴图清晰度（2048? 官方默认）与 UE 无 PBR 补偿方案的实际观感

方案 C（快速 PBR 档，轻量）：Stable Fast 3D

为什么是它：唯一「GLB 开箱 + 贴图较完整 + 秒级 + 低显存」组合，适合快速原型与大批量试错；可作为 A/B 的补充档位。

部署步骤概要

  • pip install stable-fast-3d（或 ComfyUI-3D-Pack 集成节点），权重自动下载，Windows 原生可行
  • 独立 Python 服务或 ComfyUI 节点两种形态均可对接工作台

预期效果

6GB、0.5–3 秒/资产、GLB 开箱导入 UE；albedo + tangent normal 贴图齐全；MR 为整物体标量（金属/粗糙度统一值，适合非金属材质场景资产）；几何细节轻量（27.4K 面），适合远景/道具/批量，不适合特写。许可：≤100 万美元年营收免费商用，个人创作无虞。

实测验证要点

  1. 几何细节在 UE 场景远近景的实际表现（27.4K 面是否够用）
  2. 默认 1024 纹理分辨率是否够；MR 标量对资产观感的影响
观察清单（升级 24GB 显卡后的首选，不投入本轮部署）：
  • TRELLIS.2-4B（MIT）：唯一原生 PBR 四通道 GLB（BaseColor/Roughness/Metallic/Opacity）、任意拓扑——24GB 官方要求，HF 已有 2 个社区量化版（无实测）。
  • Pixal3D（MIT，SIGGRAPH 2026）：近重建级保真 + PBR 纹理 GLB + 单图/多视角，基于 TRELLIS.2 backbone，ComfyUI 节点现成（Windows 支持明确）。若其 low_vram 1024 档在 16GB 实测可行，可提前转正——建议在方案 A/B 实测时一并试跑验证。

六、与现有工作台（server.mjs）对接方式

已确认工作台现状：手写路由的原生 Node server，具备 multipart 图片上传、文件落地、异步任务创建 + 轮询（/api/tripo/upload → generate → query → download） 完整骨架，config.json 有 comfly/tripo 配置节。本地模型接入只需「镜像」这套语义：

  1. 新增配置节 local3d：{ engine: "hunyuan2.1" | "comfyui" | "sf3d", baseUrl, outputDir }，与现有 tripo 节并列，前端控制台加「引擎切换」
  2. 新增路由组 /api/local3d/*：upload（复用现有 multipart 解析与图片落地，或直接传本地文件路径）、generate（提交任务）、query（轮询状态）、download（取 GLB）——四个接口语义与现有 /api/tripo/* 一一对应，改动集中在新增一个 adapter 模块
  3. ComfyUI 路线最省事（方案 B/C）：server.mjs 直接调 ComfyUI REST API——POST /prompt 提交工作流（把输入图路径填进加载节点参数）、GET /history/{prompt_id} 轮询、完成后从 ComfyUI 输出目录取 GLB，现有异步轮询骨架直接套用
  4. Hunyuan3D-2.1 路线（方案 A）：官方脚本无 HTTP 接口，需包一层本地 HTTP 服务（子进程调用 + 任务队列 + 状态接口），工作台只多一个 baseUrl 配置；或若官方 ComfyUI 集成可用则同 ComfyUI 路线
  5. 输出产物（GLB + 贴图）落到工作台 Assets/Models/<name>/，与现有 Tripo 下载目录结构一致，后续 ⑤ 批量导入 UE 的 unreal Python 脚本无需改动
